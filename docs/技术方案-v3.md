# 德语作文 AI 批改系统技术方案 v3

状态：试点实现版

实现仓库：/Users/bilibili/deutsch-grader

v3 不重写 v2 的方向，而是把 v2 中“说了但没落地”和“落地会算错”的部分改成可执行规格。核心仍是固定工作流、代码计分、配置版本化、教师两道人工关口和持续校准。

## 1 与 v2 的关键差异

| 主题 | v2 | v3 |
| --- | --- | --- |
| 计分 | 代码写死叙事题档位和五项映射 | S4 读取题型 YAML 的档位、缺项规则、结构规则、封顶和标题扣分 |
| 错误去重 | 模型自由 pattern，全篇同类型计一次 | 受控 error_code；按 code 聚合；重复出现按递减权重；重叠片段只留主类型 |
| 计分顺序 | 先扣标题再封顶，取整未统一 | 求和 → 封顶 → 固定扣分 → 钳制 → 最后一次性取整 |
| 证据校验 | 不是原文子串就按 false | 变 unknown；参与计分的字段不确定时不出可发布总分 |
| 教师改判 | 只记录 verdict | 每次改判/补录生成新 reviewed 分数版本；AI/复核/终审三口径 |
| 队列 | run_id + stage + attempt 口头保证 | 数据库租约、幂等键、最大尝试次数、领取事务 |
| 额度 | 余额字段 | 预留—结算—释放三段账本，同一事务检查剩余量 |
| 多租户 | 所有表口头带 tenant_id | 子表带 tenant_id；复合唯一键；对象租户前缀；跨租户测试；Postgres/RLS 草案 |
| 隐私 | 原图到期删除、画像删除 | 增加脱敏副本硬门禁、同意版本、派生数据保留矩阵、阶段正文清理 |
| 评测 | 20 篇盲测和点估计门禁 | 最小 50 篇、QWK 建议 100 篇、成对 bootstrap CI、合成数据拒绝发布 |
| 确定性 | 同一转写稿每次得分相同 | 固定阶段产物下 S4 确定；端到端重跑有稳定性边界 |

## 2 目标与非目标

目标：

- 教师确认转写后，系统稳定给出可解释的三维分数和修改清单。
- 新增题型通过新 YAML 和回归集接入，不改 S4 代码。
- 每个分数可追溯到错误码、片段、要素证据、配置版本和阶段产物。
- 教师改错、改法过度、补录漏错能立即反映到复核分。
- 多租户隔离、额度可控、数据可删除、审计可查。

非目标：

- 不替代教师终审；AI 分数不直接作为最终成绩。
- 不让模型自由决定下一步；辅导 agent 不参与打分。
- 不在未验证模型上自动切换。
- 不追求零人工；转写确认和抽样复核长期保留。


服务边界：

- API 只做鉴权、校验、编排和展示，不直接打分。
- worker 按阶段消费任务；模型调用在 worker 内完成。
- S4 是纯函数，可离线重放。
- 配置发布和质量门禁是独立流程；未通过报告不能激活。

## 4 配置模型

一种题型一份 YAML，包含：

- task_id、version、name、level、rubric_id、rubric_version。
- prompts：S1、S2、S2b、S3、S5 的独立版本引用。
- model_routes：每步的路由名。
- error_types：类型、权重、影响级别。
- error_codes：受控 code、所属 type、展示标签、示例。
- dedup：repeat_weight、pattern_cap、动词结构按句计和上限。
- language_rubric：档位表、默认分、可懂度上下限。
- checklist：字段 key、类型、问题文本。
- content：离题字段、required 表达式、detail 表达式、bands。
- structure：zero_if、order_ok、ending_ok、bands。
- length：单位、是否排除标题、封顶规则。
- title：是否必填、扣分。
- rounding：步长。

规则表达式只支持 and/or/not/eq/ne/gt/gte/lt/lte/field/const。加载时校验：

- 错误码唯一，且 type 必须存在。
- 语言档位 max_points 严格递增，score 非递增，default 不高于最后一档。
- content/structure 的 bands 必须以无条件兜底结束。
- length caps 必须按 lt 排序且唯一。
- checklist key 唯一；规则引用的字段必须存在，或属于派生字段。
- 五个阶段都必须有 prompt 和 route。
- 同一题型激活前必须有 pass 状态的 gate_report。

## 5 阶段契约

| 阶段 | 输入 | 输出 | 代码校验 |
| --- | --- | --- | --- |
| S1 | 已确认脱敏的图片、题目 | title、逐行 lines、illegible、redactions | title 为字符串或 null；lines 非空；redactions 非负 |
| S2 | level、错误码词表、句子数组 | errors：sid、original、corrected、span、code、pattern、certainty、rule | sid 存在；original 能在该句定位；code/type 合法；rule 非空；最小改动检查 |
| S2b | 单句 + 一组候选修改 | verdicts：通过 / 改法需调整 / 不成立 | 每个 error_id 必须有 verdict；改法需调整必须给 alt；checks 全为布尔 |
| S3 | 题目、字段问题、句子数组 | fields：value + evidence；sentences：逐句 comprehensible | 所有字段存在；true 必须有原文证据；活动 item 的 sid 和 text 必须匹配；逐句标记必须覆盖所有 sid |
| S4 | 错误、要素、逐句可懂、词数、标题 | language、content、structure、total、trace | 纯函数；输入缺失抛错，不返回部分分 |
| S5 | 句子、确定错误、要素、计分说明 | 三段中文评语 + 一句德语鼓励 | 引文必须是原文子串；德语不超过 12 词；不含分数、姓名 |

阶段产物保存 schema_version、input_hash、output_sha、parent_id、selected、model、token 和延迟。下游只读 selected 产物，重试不会混用。

跨度单位统一为 Python Unicode 码点，半开区间。存储时转成整篇绝对偏移，展示时按 sid 还原到句内。

## 6 计分规范

### 6.1 输入

- 只计 effective 为真的错误。
- effective 由状态机派生：certainty 为确定、terminal_status 为 confirmed、非重叠次标签、教师未驳回。
- teacher_action 为 reject 或 over_edit 的错误不计分。
- 建议核对只展示，不计分。

### 6.2 语言分

- 动词结构缺失按 sid 计，每句 per_sentence 点，单篇上限 cap。
- 其他错误按 error_code 聚合；第 n 次出现按 weight × (1 + repeat_weight × (n-1))，单 code 不超过 pattern_cap。
- 点数落在语言档位表；超过最后一档用 default_score。
- 可懂比例低于 ceiling_below_ratio 时封顶；达到 floor_min_ratio 时保底；0 可懂直接 0。

### 6.3 内容与结构

- 离题字段为假时内容 0。
- required 中假值数量为 missing_count；detail 决定是否拿满分。
- content bands 按顺序首个命中。
- structure 先看 zero_if；再算 order_ok 和 ending_ok；bands 按顺序首个命中。

### 6.4 总分

~~~text
raw = language + content + structure
raw = min(raw, 命中的 length cap)
raw = raw - 固定扣分
raw = clamp(raw, 0, total_max)
total = 按步长四舍五入一次
~~~

权重限定为 0.5 的增量；内部用 Decimal 比较档位和取整，避免浮点边界。

## 7 状态机

提交：

~~~text
uploaded → transcribing → awaiting_confirmation → queued → grading → ready_for_review → finalized
                                      ↘ needs_manual ↗
~~~

运行：

~~~text
pending → running → ready_for_review → finalized
              ↘ needs_manual
~~~

错误：

~~~text
candidate → confirmed
candidate → downgraded
candidate → rejected
candidate → secondary
confirmed → teacher_confirmed
confirmed → teacher_rejected
confirmed → teacher_corrected
~~~

任务：

~~~text
queued → running → done
   ↑        ↘ queued（退避重试）
   └──────── dead（超过 max_attempts）
~~~

额度：

~~~text
reserved → settled
reserved → released
~~~

任何状态迁移都要写审计；已 finalized 的作业不重算，除非管理员显式开新 run。

## 8 多租户与数据模型

试点使用 SQLite，所有业务表带 tenant_id。关键约束：

- submission、run、transcript、stage_output、error_item、checklist_item、score、teacher_review 都有 (tenant_id, id) 唯一索引。
- API 的每次读取先按 tenant_id 过滤；跨租户返回 404，不泄露对象存在性。
- 对象 key 以 tenant_id 开头；读取时再次校验前缀和存储根路径。
- worker 的 job 带 tenant_id；领取后只操作同租户数据。

生产迁移到 Postgres 时：

- 父表用 (tenant_id, id) 复合主键，子表用 (tenant_id, parent_id) 复合外键。
- 所有含 tenant_id 的表启用 RLS；应用连接在事务内设置 app.tenant_id。
- 管理后台、worker、教师 API 使用不同数据库角色，最小权限。
- 迁移草案见 app/sql/schema.postgres.sql；上线前需要真实 Postgres 回归和渗透测试。

## 9 隐私与生命周期

| 数据 | 保留 | 删除/清理 |
| --- | --- | --- |
| 原图 | 转写确认后至多 120 天 | 到期删除对象并写 deleted_at |
| 脱敏副本 | 与批改同一学期 | 学期末清理 |
| 转写稿 | 学期内 | 学生离校/撤回同意后删除 |
| 阶段原始输出 | 默认 30 天 | 清理正文，保留 input/output 哈希和状态 |
| 错误、分数、评语 | 学期内 | 终审记录按学校政策保留；引文随转写清理 |
| 校准样本 | 脱敏后保留 | 需要独立合法依据；撤回同意时删除 |
| 画像 | 同意范围内 | 撤回后删除 pattern 和 positive evidence |
| 审计 | 法定/合同期限 | 只追加；detail 不含作文原文和姓名 |

同意表记录 notice_version、purpose_version、scope、granted_at、expires_at、revoked_at 和证据引用。S1 只接受已确认脱敏副本；没有脱敏确认时转写被拒绝，避免原图直接进模型。

## 10 模型路由与额度

- 每个阶段绑定路由；S2 和 S2b 必须不同家族。
- 路由固定 provider、model、family、base_url_env、api_key_env 和参数。
- 套餐来源登记 unit、total、window、reset_at、concurrency、rate、terms_ok、expires_at、fallback_order。
- 调度顺序：已验证套餐 → 另一套餐 → 按量兜底。
- 每次调用先预留估算额度；调用后用实际 token 结算；失败释放。
- 按量来源有 monthly_budget；达到上限跳过并告警。
- 真实上线前核对服务商条款是否允许后端 API 调用；coding 套餐若只允许 IDE，标为不可用。

## 11 评测与发布门禁

数据集分 tune、blind、regression：

- tune 用于调规则，blind 在冻结规则后只跑一次，regression 只增不改。
- 每个新题型单独验收；试卷、级别和短/长文分层抽样。
- 教师双评独立打分；分歧用裁决共识或分层评分者模型处理。

指标：

- 完全一致率、±0.5 一致率、MAE、偏差、QWK。
- 确定错误精确率、错误召回率、最小改动违规。
- 同一转写稿跑 3 次的完全一致率和单篇极差。
- 分组偏差：短文、错误密集、字迹差。

门禁：

- release 至少 50 篇标注，QWK 建议 100 篇；报告成对 bootstrap 95% CI。
- 合成数据只能 demo，不能发布。
- QWK 低于 0.80、±0.5 低于 90%、MAE 高于 0.35、稳定性低于 90%、有最小改动违规，均阻止。
- 相对 baseline：±0.5 下降超过 3 个百分点、MAE 上升超过 0.05、QWK 下降超过 0.03，阻止。
- 配置激活必须有 pass 报告；fail 和 demo 报告不能激活。

## 12 教师端

- 上传/文本录入：按学生和作业创建提交。
- 确认转写：原图与转写对照；[?] 标黄；确认后固定版本并排队。
- 错误清单：默认展示确定错误；可标 AI 改错、改法过度、修正改法；建议核对折叠。
- 分数：三维分、总分、计分说明、封顶/扣分原因。
- 终审：可改任一维度，必须选原因；生成 reviewed 和 final 版本。
- 导出：学生版只含修改清单、评语和鼓励语；班级报告含错误分布。
- 看板：改分率、平均改分方向、确定错误驳回率、建议核对比例、[?] 比例、额度。

教师改判后必须立即重算复核分；补录漏错同样触发重算。次标签不能单独确认，避免同片段重复计分。

## 13 学生画像与练习

画像只来自教师确认过的错误：

- 出现率 = 该 error_code 每 100 词出现次数，取最近 5 篇。
- active：最近 3 篇都出现。
- improving：出现率连续下降。
- mastered：教师确认有该结构的正确使用，并且后续正式作文未再出现。

当前实现做到 pattern 聚合、班级/个人视图和教师正向证据；练习推荐和受限辅导 agent 留在下一阶段。辅导 agent 只能读本人画像、取练习、判答案、给提示，不能改分或代写。

## 14 角色与运营

| 角色 | 职责 |
| --- | --- |
| 教师 | 确认转写、逐条审核、改分、终审 |
| 量规负责人 | 改题型配置、看校准、批准发布 |
| 管理员 | 账号、租户、额度、审计 |
| 数据保护负责人 | 同意、撤回、删除请求、影响评估 |
| 工程/运维 | 引擎、队列、门禁、模型路由、告警 |

KPI：

- 质量：双评 ±0.5 一致率、MAE。
- 省时：单篇审核时间相对手工批改下降 50% 以上。
- 采纳：终审未改分比例达到 80% 以上。
- 周转：上传到可审核的中位时间当天完成。
- 稳定性：失败率低于 2%，需人工比例可控。

## 16 风险

| 风险 | 应对 |
| --- | --- |
| 手写转写错误被当成学生错误 | 教师确认；[?] 相关只做建议核对；脱敏副本硬门禁 |
| 小样本过拟合 | tune/blind 冻结；至少 50 篇；持续双评 |
| 模型悄悄更新 | 固定版本和 fingerprint；更新走同一门禁 |
| 套餐条款变化 | 条款核对留档；多来源；按量兜底上限 |
| 复核员与找错员同错 | 不同家族；精确率持续统计 |
| 教师过度依赖 AI | 逐条确认；抽样漏错；终审必须选原因 |
| 画像标签化学生 | 只对教师和本人可见；只描述错误类型 |
| 多租户泄露 | RLS、复合外键、对象前缀、跨租户测试 |
